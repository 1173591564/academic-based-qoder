# Memory 准入策略

在写入或修改任何 memory 之前，必须满足以下规则。

## 允许写入的 5 种类型

| # | 类型 | 数量模型 | 操作方式 |
|---|------|----------|----------|
| 1 | 踩坑经验（问题+解法） | 可累积多条 | 新问题=新建，同问题=更新 |
| 2 | 项目定位与架构 | 每项目仅 1 条 | 只更新，不新建 |
| 3 | 用户行为偏好 | 少量稳定条目 | 合并更新，不重复建 |
| 4 | 重要决策及理由 | 按决策点累积 | 决策变了=更新原条目 |
| 5 | 环境事实 | 按事实累积 | 变了就更新 |

**不属于以上 5 类的，一律不写入。**

## 操作约束

1. **写前必查重** — 写入前先 SearchMemory 检查是否已有同类条目。有则更新，无则新建。
2. **不与 rules/skills 双重存储** — 信息已在 `{IDE_DIR}/rules/` 或 `{IDE_DIR}/skills/` 中的，不写入 memory。
3. **单条精简** — 每条 memory 控制在 3-5 句话，写结论不写过程。标题即核心判断。
4. **关键词必须精准** — 不用泛词（「代码」「修复」「问题」），用具体触发词。
5. **Knowledge 卡片不手动写** — 系统自动管理，agent 不主动创建或修改。
6. **过时即删** — 发现 memory 与当前事实矛盾时，立即更新或删除。

## 明确禁止写入的

- 单次任务的执行细节（「这次怎么修的 bug」的流水账）
- task_summary 类型（除非是可复用的经验模式）
- 已写入 rules/skills 的内容
- 一次性调试过程
