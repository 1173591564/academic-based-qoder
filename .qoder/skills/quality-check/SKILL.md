## 触发
当用户说"检查论文质量"、"这篇论文靠谱吗"、"评估一下这篇"、"论文自检"时执行此流程。

## 流程

### Step 1: 定位论文
通过搜索或 paper_id 定位目标论文。

先检查是否有预计算评分：
```bash
python -m scholar quality-score <ULID>
```
如果已有 `output/notes/<ULID>-quality.json`，直接读取预计算的 7 维度评分作为起点。
同时读取 `output/notes/<ULID>.md` 预生成笔记快速了解论文概况。

### Step 2: 元数据完整性检查
```bash
python -m scholar info <ULID>
```
检查：
- 标题是否完整（非 null）
- 作者列表是否合理（不是空列表或包含乱码）
- 年份是否在合理范围
- 会议/期刊名称是否可识别

### Step 3: 结构完整性
从 `output/parsed/` JSON 分析：
- **章节结构**：是否有标准的 Introduction / Method / Experiments / Conclusion？
- **公式密度**：formulas 数量是否与论文类型匹配？
- **引用数量**：citations 数量是否合理？（太少可能遗漏，太多可能是综述）
- **摘要**：abstract 是否完整？

### Step 4: 方法论评估
深度阅读论文核心方法部分：
- **问题定义**：是否清晰定义了要解决的问题？
- **假设合理性**：核心假设是否有依据？
- **方法创新性**：与引用列表中的前置工作相比，有什么本质创新？
- **实验充分性**：实验是否能支撑论文的声明？
- **消融实验**：是否有消融实验验证各组件的贡献？

### Step 5: 引用准确性
检查论文引用的关键工作：
```bash
python -m scholar search "<被引论文关键词>"
```
- 引用的前置工作是否准确？
- 是否遗漏了重要的相关工作？
- 自引比例是否过高？

### Step 6: 可复现性评估
- 是否公开了代码？
- 实验设置描述是否足够详细？
- 超参数是否列出？
- 数据集是否可获取？

### Step 7: Lean4 形式化对照（如适用）
检查论文中的核心方法是否在 Lean4 的 AiEvolution 项目中有形式化定义：
```bash
python -m scholar graph-query <概念名>
```
如果 Neo4j 中有对应的 Innovation 节点，说明该方法在学术演化中有重要地位。
同时检查 REPLACES 关系：该方法替代了哪些旧方法？

### Step 8: 输出质量报告
输出到 `output/notes/quality-<paper_id>.md`：

```markdown
## 论文质量评估: <title>

### 基本信息
- 作者/年份/会议: ...
- 引用量(本地库内): N

### 评分卡
| 维度 | 评分(1-5) | 备注 |
|------|----------|------|
| 元数据完整性 | ... | ... |
| 结构完整性 | ... | ... |
| 问题定义 | ... | ... |
| 方法创新性 | ... | ... |
| 实验充分性 | ... | ... |
| 引用准确性 | ... | ... |
| 可复现性 | ... | ... |
| **综合** | **...** | |

### 优点
1. ...

### 问题
1. ...

### 建议
- ...
```

## 注意事项
- 质量评估要基于论文的实际内容，不要仅凭会议/期刊名气打分
- 对于预印本（arXiv），适当降低"引用量"维度的权重
- 如果论文的某些维度无法评估（如缺少实验部分），标注"无法评估"
