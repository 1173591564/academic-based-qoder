# 采用双副本数据策略分离全局知识库与工作区上下文

_来源：bc6e785 → 71a964c 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
随着项目从开发模式转向多项目工作区模式，原有的单一输出目录结构无法区分“全局共享知识”（如解析后的论文库 parsed/）和“项目特定产出”（如草稿 drafts/、笔记 notes/）。MCP 服务器与 CLI 之前存在路径读取不一致的问题，且缺乏明确的工作区初始化机制。

## 决策驱动
- 支持多项目并行开发
- 避免全局知识库冗余复制
- 统一 MCP 与 CLI 的路径配置
- 保持开发模式零配置兼容

## 备选方案
- **Windows  junction 链接 parsed/** _（已否决）_ — 优点：物理上隔离但逻辑上共享；缺点：过度工程化，增加跨平台兼容性风险，且代码层已可通过配置解决
- **完全服务层提取（Service Layer）** _（已否决）_ — 优点：从根本上解决 MCP 调用性能问题；缺点：重构成本过高（需新建 10+ 文件并修改 39 个命令），不适合当前阶段
- **双层路径配置（SCHOLAR_HOME + WORKSPACE_DIR）** — 优点：逻辑清晰，parsed/ 等大数据量目录全局共享，drafts/notes/logs 按工作区隔离；开发模式下自动回退至同一目录，无行为变更；缺点：增加了路径配置的复杂度，需确保所有模块正确引用新配置变量

## 决策
在 `scholar/config.py` 中引入 `WORKSPACE_DIR`（由环境变量或 cwd 决定），将 `DRAFTS_DIR`, `NOTES_DIR`, `LOGS_DIR` 迁移至工作区下，而 `PARSED_DIR` 等保留在全局 `SCHOLAR_HOME`。新增 `init-workspace` 命令用于初始化项目目录结构，并统一 `scholar_mcp/server.py` 使用 `scholar.config` 中的路径变量。

## 影响
实现了全局知识库与项目上下文的物理隔离，避免了每个项目重复存储庞大的解析数据。MCP 服务器与 CLI 现在基于统一的配置源读取路径，解决了部署不一致问题。开发环境保持无缝兼容，但生产/多项目环境下需显式执行 `init-workspace`。
