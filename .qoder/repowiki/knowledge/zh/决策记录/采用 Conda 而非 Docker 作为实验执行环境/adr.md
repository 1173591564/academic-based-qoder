# 采用 Conda 而非 Docker 作为实验执行环境

_来源：bc51cd3 → 35a8f17 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
在“实验复现”工作流中，需要为论文代码配置运行环境。需要在隔离性、配置复杂度和用户现有习惯之间做出选择。

## 决策驱动
- 实施轻量级（避免引入重型容器运行时）
- 用户习惯匹配（学术圈普遍使用 Conda）
- 开发调试便利性

## 备选方案
- **使用 Docker 统一执行环境** _（已否决）_ — 优点：环境隔离彻底，可复现性最强；缺点：增加系统复杂度，镜像构建慢，GPU 透传配置麻烦，用户学习成本高
- **使用 Conda 管理环境（选中）** — 优点：轻量，学术界标准工具，用户已有环境基础，易于调试；缺点：隔离性不如 Docker，可能存在依赖冲突

## 决策
在 `scholar/cli.py` 的 `exp-setup` 和 `exp-run` 命令中，默认使用 Conda 创建和管理实验环境，并提供 `--use-docker` 作为可选的高级模式（但主要路径为 Conda）。

## 影响
降低了“实验复现”功能的接入门槛，提高了执行成功率。但牺牲了部分环境隔离性，需依赖用户正确维护 Conda 环境。
