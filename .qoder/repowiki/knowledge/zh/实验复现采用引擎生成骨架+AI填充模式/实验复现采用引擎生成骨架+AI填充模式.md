# 实验复现采用引擎生成骨架+AI填充模式

_来源：7729a25 → 7877e84 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
现有的 exp-setup 仅打印指令而不执行，exp-run 缺乏沙箱隔离，且引擎不提供代码脚手架，导致 AI 大脑需从零生成代码，复现流程断裂且不安全。

## 决策驱动
- 开发效率
- 执行安全性
- 结果可比性

## 备选方案
- **AI 大脑从零生成全部实验代码** _（已否决）_ — 优点：灵活性最高；缺点：重复劳动多，易出错，缺乏标准结构，难以自动化对比指标
- **引擎生成带 TODO 的代码骨架 + Docker 沙箱执行** — 优点：提供标准化项目结构（model.py, train.py 等），AI 仅需填充核心逻辑；Docker 确保环境隔离与安全；自动提取结构化指标便于前端对比；缺点：需维护代码模板生成器；依赖 Docker 环境

## 决策
新建 scholar/exp_codegen.py 根据论文元数据生成实验代码骨架；修改 execution_ops.py 使 exp-setup 实际执行环境创建，exp-run 支持 Docker 沙箱模式，并增加结构化指标提取逻辑。

## 影响
实现了从论文到可运行代码的半自动化闭环；前端可通过 ExperimentMetrics 组件直观对比复现结果与原文指标；增加了系统对 Docker 的运行时依赖。
